## Drydock workflow

Each GitHub issue is implemented in its own Drydock worktree. When `DOCK.md` is present, read it first, stay inside that worktree, record assumptions there, and implement only that issue. Do not switch branches, rebase, merge, or bypass review and QA gates. Run the repository tests and finish with a reviewable commit.
